# 岗位评估黑盒用例
在本目录运行 `.\.venv\Scripts\python.exe main.py`。新环境先创建 venv，再安装 requirements.txt。工作台须运行在 8000 端口的真实模式，已有已确认的画像、已有岗位和可用的模型、联网搜索及高德配置。运行会调用工作台已有服务并保存真实评估报告。可用环境变量 WORKBENCH_URL 指定另一工作台。

1. 在 config/cases/test_job_match.xlsx 的第一张表填写配置，岗位 ID 使用文本格式。当前画像由工作台读取。每行可选检查必备项数、匹配分、某一条要求的匹配判断。数字填 Excel 数值，空白跳过，文本 null 表示预期空分数。逐项判断用原文关键词唯一定位；请选无需猜测模型措辞的稳定词语。
2. 每个新 ID 在 GlobalVar.py 登记一次。项目根目录的 执行清单.xlsx 每行写一个要跑的完整 ID，同一批不允许重复。映射值是 Python 模块名（如 cases.test_job_match），每个脚本提供 Case 类。每条用例新建实例，run() 返回结果，teardown() 在用例结束时收尾。起点 Default 取第一项，具名起终点要求精确且唯一，终点空白时仅在只有一个候选时自动确认。
3. reports/月/日期/批次开始时间/summary.csv 汇总 PASS、FAIL、ERROR、NOT_RUN。打开用例目录的 report.md 查看测试条件和每项预期、实际值；run.log 记录执行步骤及异常堆栈。NOT_RUN 用例只有未运行说明。
4. 示例画像核对时为本科、修订号 4，两份岗位均有明确本科学历门槛。若用户修改当前画像或岗位需求，请相应核对 Excel 预期。工作台同时只允许一个活动，等待地点配置错误时脚本会结束自己发起的待输入运行。
